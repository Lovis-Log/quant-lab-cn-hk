## 1. 两条产品线必须同时保留

项目从这里开始保留两条可独立推进的产品线：

| 产品线 | 分支 | 定位 |
| --- | --- | --- |
| 任务式学习版 | `codex/learning-center-v2` | 保留新手任务、测验、目标、进度和原学习中心；以后可能继续开发 |
| 文字手册版 | `codex/manual-reading-v1` | 使用纯阅读、检索和术语解释的“使用手册”；按本文分阶段实现 |

强制规则：

1. `codex/learning-center-v2` 不得被删除、强制推送或用文字手册版整体覆盖。
2. 新对话应从包含本交接文档的 `codex/learning-center-v2` 最新干净提交创建 `codex/manual-reading-v1`。
3. 文字手册代码只提交到 `codex/manual-reading-v1`；不要自动合并回任务式学习版。
4. 两条线需要共享的缺陷修复，应保持为小而独立的提交，再按需分别 cherry-pick；不要用整分支合并混入另一条产品线。
5. 不删除旧安装包、旧打包应用、标签或历史 Release。任何清理和发行操作都必须由用户在当前任务中明确授权。
6. 不修改或重写已经发布的 Git 历史，不使用强制推送。

内容基线 `46859ee` 同时包含任务式学习版源码和已验收的 95 篇内容草稿，可作为两条产品线共同的内容起点。

## 2. 数据兼容：撤销“删除旧学习数据”的计划

`docs/CLAUDE_MANUAL_CONTENT_HANDOFF.md` 第 2 节曾计划通过 schema v5 删除任务、测验和进度数据。该决定从本交接文档起被撤销，不得执行。

原因：任务式学习版当前使用 SQLite schema v4。若文字手册版把同一资料库升级到更高版本，旧版会因“数据库版本比当前软件新”而拒绝打开；若删除学习表或数据，也会破坏用户以后继续使用任务式学习版的可能性。

因此，文字手册版必须遵守：

- 接入手册不升级 `PRAGMA user_version`，当前保持 schema v4；
- 不删除、清空、重命名或迁移 `learning_progress`、`learning_quiz_attempts`、学习目标、课程实验或旧学习笔记数据；
- 不删除 `learning.py`、`guidance.py`、`learning_store.py`、`ui_guidance.py`、`ui_learning.py` 及其测试；
- 文字手册版可以不在默认界面显示旧任务体系，但旧源码和数据库内容必须保留；
- 所有开发和 GUI 验收使用独立的 `QUANT_LAB_DATA_DIR`、测试 AppId 和测试凭据目标，不能修改真实用户资料库；
- 如果未来确实需要 schema 变化，必须先单独设计双向兼容或资料库复制方案，并由用户明确批准，不能作为手册接入的顺带改动。

## 4. 最终产品方向

文字手册版的目标是降低学习混乱感，采用阅读和检索方式：

1. 顶栏入口显示“使用手册”。
2. 手册仍使用右侧停靠面板，不新增独立网页应用。
3. 三个主入口为“快速开始”“功能说明”“专业知识库”。
4. 不要求任务、打卡、完成度、测验、错题、学习目标或首次欢迎流程。
5. 专业文章默认先显示白话解释，公式、符号、推导和例子可以继续展开阅读。
6. Quant Academy 的固定样本实验可以保留，但在文字手册版中不承担任务、进度或测验职责。
7. 设置中的“新手模式（关闭为专业模式）”最终改为“显示详细解释提示”，只影响解释密度，不改变金融计算。
8. DeepSeek 仍只在用户明确发送时请求；手册阅读、索引和搜索必须完全离线可用。

这些是文字手册分支的产品决定，不得反向删除任务式学习分支的能力。

## 6. 阶段 1：内容运行时基础（新对话只做这一阶段）

### 6.1 目标

建立一个与 Streamlit、SQLite 和网络无关的只读内容层，让程序能够离线发现、解析、校验和查询 10 篇手册与 85 篇专业文章。此阶段不改变任何可见界面。

建议新增独立模块，例如：

```text
quant_lab/manual_content.py
tests/test_manual_content.py
```

具体命名可根据现有模块边界微调，但不得把解析逻辑写进 `ui_guidance.py` 或其他 UI 模块。

### 6.2 最小数据模型

内容层至少应表达：

- 手册 ID、标题、正文、来源文件；
- 专业文章的 frontmatter：`id`、`title`、`english_title`、`aliases`、`category`、`software_status`、`related_modules`、`prerequisites`、`related_articles`、`source_ids`、`last_verified`；
- Markdown 正文；
- 分类顺序、稳定 ID 查询、关联文章查询；
- 面向后续 UI 的纯文本搜索字段，至少覆盖中文标题、英文标题、别名和正文。

不要在阶段 1 建立数据库表、学习进度、已读状态、收藏、远程索引或向量数据库。

### 6.3 资源路径

- 源码运行和未来 PyInstaller 运行都必须能找到只读内容资源；
- 路径解析应复用项目现有资源根思路，不能依赖当前工作目录；
- 内容文件不得复制到用户资料库后再作为唯一来源；
- 阶段 1 只证明加载策略和离线测试，不构建安装包；
- 资源缺失、frontmatter 无效、ID 重复或引用不存在时必须显式报错，不能静默跳过。

### 6.4 验收标准

阶段 1 完成时必须有自动测试证明：

1. 离线加载 10 篇手册和 85 篇专业文章；
2. 85 个专业 ID 唯一；
3. 所有 `prerequisites`、`related_articles` 均能解析；
4. 必填 frontmatter 缺失、非法 `software_status`、重复 ID、缺失关联 ID 会失败；
5. 可按稳定 ID 取得文章；
6. 可按分类列出文章；
7. 中文标题、英文标题和别名可以被纯文本搜索；
8. 测试不联网、不写真实用户目录、不导入 Streamlit；
9. 现有任务、测验、进度、Academy、研究笔记、AI、回测和数据库测试保持通过；
10. UI、数据库 schema、`VERSION` 和发行文件没有变化。

阶段 1 不得：

- 改顶栏按钮或右侧面板；
- 隐藏或删除旧学习中心；
- 改设置标签；
- 删除任务、测验、目标或进度；
- 修改 SQLite；
- 开始阶段 2 的 UI。

## 11. 每阶段通用工程规则

1. 开始前检查 Git 状态；有未提交文件时先保护，不能覆盖归属不明的修改。
2. 工作树干净时创建本阶段恢复分支。
3. 只修改本阶段需要的文件，不顺带重构其他模块。
4. 核心内容/计算模块不导入 Streamlit。
5. 不访问或修改真实用户数据库、缓存、日志、附件或凭据。
6. 不调用付费模型 API，不把任何密钥写入源码、日志或测试。
7. 运行适用测试；不得跳过失败测试宣称完成。
8. 完成后检查改动范围，commit 并 push 到当前产品线分支，不强制推送。
9. 推送后核对远程提交与本地一致，提供提交链接。
10. 不打包、不改版本、不创建标签、不发布 Release，除非用户当前任务明确授权。
