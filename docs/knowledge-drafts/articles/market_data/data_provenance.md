# 数据来源与时间戳（Data Provenance）

## 快速理解

### 一句话解释

数据溯源是记录“这份数据来自哪里、什么时候收到、用什么口径、有没有缓存或失败”，让研究结果能被复核；它不是行情本身，也不能把接收时间变成交易所报价时间。

### 它解决什么问题

它解决三个问题：知道数据来自哪个市场和接口；区分本次上游响应、缓存读取和失败后保留的旧数据；在实验档案中保留来源、时间、复权和币种，便于复算。

### 最常见的误解

- **“来源名字就够了”**：同一市场可能有主接口和回退接口；来源、接收时间、复权和币种要一起记录。
- **“接收时间就是行情时间”**：`received_at` 是本机收到响应的时间，不是交易所成交时间，也不是报价时间。
- **“页面刷新就是重新获取”**：页面重绘可能只是读缓存；缓存读取不更新上次成功获取时间。
- **“失败后保留旧数据等于新数据”**：失败会保留最近有效数据并标明可能过期；旧数据不是新行情。
- **“溯源只需要在实验里写一句来源”**：可复现需要来源、时间、口径、参数、快照和指纹一起保存。

## 软件实践

### 在 Quant Lab 哪里出现

- 行情数据合同：市场、规范代码、来源、币种、复权、接收 UTC 时间、缓存标记、缓存年龄、更新结果和错误。
- 市场页“数据更新状态”和“数据说明”。
- 证券名称/候选目录的缓存来源和获取时间。
- 研究实验档案：保存来源、接收时间、复权、市场、代码、名称、参数和两份行情快照。
- 数据错误日志：记录请求失败和详细异常，路径在用户资料库 `logs/data_errors.log`。

### 输入、输出和单位

| 字段 | 含义 | 单位/格式 |
| --- | --- | --- |
| `source` | 数据来源或回退来源 | 文本，例如“腾讯证券 · AKShare” |
| `market` | 市场 | “A 股”或“港股” |
| `symbol` | 规范代码 | 字符串 |
| `currency` | 价格/成交额币种 | CNY 或 HKD |
| `adjustment` | 复权口径 | 不复权/前复权/后复权 |
| `received_at` | 本机收到响应的时间 | UTC 时间戳；页面显示北京时间 |
| `cached` | 是否来自缓存 | 布尔 |
| `cache_age_seconds` | 距上次成功获取的秒数 | 秒 |
| `update_result` | 本次检查结果 | 取得新数据/数据未变化/请求失败 |
| `update_error` | 更新错误 | 文本或空 |

`received_at` 是时间戳，`cache_age_seconds` 是时长；两者都不是价格或收益率。

### 结果应该怎么读

- 先看来源，再看行情日期和接收时间；不要把接收时间写成“行情时间”。
- 看缓存状态：本次上游响应、缓存/会话快照、失败后保留的旧数据，含义不同。
- 失败时保留旧数据并显示“可能过期”；不要因为页面还能显示价格就认为上游成功。
- 看到港股回退来源时，记录“东方财富请求失败后回退”，不要把回退来源和主来源混为同一批次。
- 复算实验时，使用档案中的来源、接收时间、复权、参数和快照，不要用当前行情替代。

### 当前软件边界

- 软件记录来源和接收时间，但不提供交易所授权时间戳、报价时钟或延迟测量。
- `received_at` 来自本机，不能证明交易所时间；缓存读取不会更新它。
- 溯源记录是本地 SQLite/文件，不是第三方签名或不可篡改审计；用户可以修改本地文件。
- 来源字符串由程序拼接；上游接口、字段和回退行为可能变化；NEEDS_REVIEW（核验日期：2026-10-22）。
- 当前不保存每次请求的完整 HTTP 响应头、数据源版本号或供应商修订历史。

## 专业原理

### 正式定义

数据溯源（data provenance）描述数据实体及其来源、生成/获取过程、时间、方法和责任链。一个最小可复现溯源记录应回答：

- 哪个市场、哪只证券、哪个代码；
- 哪个数据源、哪个接口、是否回退；
- 什么时间收到、对应哪个交易日；
- 什么复权口径、什么币种、什么单位；
- 经过哪些验证、是否有缓存或失败；
- 用哪些参数和快照生成了什么结果。

FAIR 原则强调可发现、可访问、可互操作和可复用；溯源元数据是可复用和可审计的基础，但它不等于数据本身正确。

### 公式与符号

设一次行情响应为 `B`，其溯源记录可以表示为：

`prov(B) = (source, market, symbol, currency, adjustment, received_at, cached, age, result, error)`

缓存年龄：

`age = now − last_successful_received_at`

其中 `now` 和 `last_successful_received_at` 必须使用同一时间基准（程序内部使用 UTC/单调时钟）；页面显示时再转北京时间。

实验指纹通常由数据快照和参数计算：

`fingerprint = H(raw_csv, signal_csv, strategy, costs, train_fraction)`

`H` 是哈希函数；指纹用于核对，不证明数据来源真实。

### 可手算的小例子

假设某次 A 股响应：

- 来源：`腾讯证券 · AKShare`
- 市场/代码：A 股 `600519`
- 行情日期：`2026-10-21`
- 接收时间（UTC）：`2026-10-22 01:30:00`
- 复权：不复权
- 币种：CNY
- 缓存：否
- 更新结果：取得新数据

换算与核对：

- 北京时间 = `2026-10-22 09:30:00 UTC+08:00`。
- 行情日期是 `2026-10-21`，不是接收日 `2026-10-22`；二者相差一天，不能把接收日当交易日。
- 如果当前是北京时间 `09:35:00`，而这次成功获取时间是 `09:30:00`，缓存年龄 = `300` 秒；这 300 秒不是行情延迟。
- 如果页面在 `09:40:00` 重绘但 `received_at` 仍是 `09:30:00`，缓存年龄变为 `600` 秒，而不是“又获取了一次新数据”。

再假设一次失败：

- 本次请求失败，页面保留上次有效数据，`received_at` 仍是上次成功时间，`update_result` 标记“请求失败/可能过期”。
- 不能把这次失败后的页面显示时间写成新的接收时间；失败不是新数据。

### 前提假设

- 本机时钟基本准确；`received_at` 是收到响应的时刻。
- 数据源字符串真实反映主接口/回退接口；程序没有隐藏来源切换。
- 缓存命中不更新成功获取时间；失败保留旧值并标记。
- 本地 SQLite/文件未被外部篡改；需要更强审计时应另行加签名或外部存证。

### 边界情况

- `received_at` 缺失：显示“未记录”，不能推断为当前时间。
- 时区/夏令时：存储 UTC、显示北京时间；其他市场需另处理。
- 缓存命中、失败保留、成功但数据未变化、手动更新。
- 港股主接口失败回退新浪；来源文字必须变化。
- 数据源修订历史、接口版本、HTTP 响应头、供应商时间戳。
- 同一交易日多次检查价格不变；不要因此认为数据没有更新或行情延迟为零。
