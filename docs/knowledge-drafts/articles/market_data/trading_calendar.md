# 交易日历（Trading Calendar）

## 快速理解

### 一句话解释

交易日历决定“哪些日期有交易、哪一天算下一个交易日”；Quant Lab 目前直接使用上游返回的实际交易日，不维护独立的交易所节假日日历。

### 它解决什么问题

它让日期过滤、样本计数、均线预热、下一交易日开盘成交、组合共同日期和收益年化有统一的时间轴。没有交易日概念，就会把周末、节假日、停牌日和数据缺失混在一起。

### 最常见的误解

- **“周一到周五都是交易日”**：法定节假日、交易所休市和特殊安排会让工作日没有交易。
- **“缺一行就是假日”**：可能是节假日、停牌、上市前日期、退市后日期或上游数据缺失；仅凭日线无法区分。
- **“A 股和港股日历相同”**：两个市场的节假日和休市安排不同，不能假设共同日期等于任一市场的全部交易日。
- **“252 就是每年实际交易日”**：252 是年化近似假设，不自动适应每个市场、年份或个股停牌。
- **“日期区间内的自然日都该有数据”**：历史日线只为实际交易日提供记录。

## 软件实践

### 在 Quant Lab 哪里出现

- 左侧“历史区间”筛选；只保留区间内的实际交易日。
- 市场页“样本交易日”、最新交易日和图表横轴。
- 策略均线窗口、回测“下一交易日开盘”执行、参数敏感性。
- 组合页对多只股票按日期做内连接，得到共同交易日。
- 年化收益和年化波动率使用 252 个年交易日近似。

### 输入、输出和单位

输入是用户选择的开始/结束日期，以及上游返回的 `date` 列。输出是经过解析、过滤、排序、去重后的交易日序列。

- `date` 是日期，不是时间戳，也没有盘中时刻。
- 样本交易日数是行数，不是自然日数。
- 两个日期之间可能包含周末和节假日；这些日期不会自动补行。
- 组合共同交易日是多个代码日期的交集，不是并集。

### 结果应该怎么读

- 先看页面显示的“最新交易日”和“样本交易日”，不要用今天日期代替最新交易日。
- 看到日期跳跃时，先判断是周末、节假日、停牌还是数据缺失；日线本身不能给出唯一答案。
- 回测中的“下一交易日”是返回序列中的下一行；如果上游漏了一行，程序无法仅凭日线知道中间是否还有交易日。
- 年化数据只是按 252 个交易日近似换算，不是“这一年实际有 252 个交易日”的声明。

### 当前软件边界

**软件已经计算或显示什么**

- 解析 `date`、按用户区间过滤、按日期升序排序、拒绝重复交易日。
- 显示样本交易日数、最新交易日和图表日期轴。
- 在回测中把信号日后的下一行当作下一交易日开盘；在组合中按日期内连接共同交易日。
- 用返回序列计算收益率、均线和样本内外切分。

**软件只间接使用什么**

- 年化收益和年化波动率使用 252 个年交易日近似。
- 自选股快照读取最近 21 天窗口，寻找最近可用日线。
- 缓存 TTL、自动刷新间隔和“下次尝试时间”使用时钟时间，不是交易日历。
- 均线窗口按“行数”而不是自然日数计算；停牌或缺失行会改变窗口覆盖的实际日历跨度。

**软件没有提供或没有建模什么**

- 独立的上交所/港交所节假日日历、半日市、特殊休市、临时停市和跨市场日历服务。
- 停牌、复牌、上市首日、退市日、IPO 日历和证券生命周期。
- 交易日完整性校验；无法判断上游漏行是休市还是数据缺失。
- 盘中交易时段、集合竞价、午休和盘后交易。
- 跨市场共同交易日的最优对齐策略；当前只做日期交集。

**核验状态**：

交易所日历和休市安排会变化；本文只描述当前软件如何使用上游日期，不声明覆盖交易所全部休市规则。相关规则和接口完整性标记 NEEDS_REVIEW（核验日期：2026-10-22）。

## 专业原理

### 正式定义

交易日历（trading calendar）是某一交易场所规定可以交易的日期集合，通常还包含交易时段、半日市和特殊休市安排。交易日历与自然日日历不同：自然日每天都有，交易日只在交易所开市时存在。

在日线研究中，交易日历至少影响：

- 观测频率：每个交易日一行；
- 收益间隔：相邻两行之间的收益；
- 执行时点：信号日后的下一行；
- 对齐方式：多资产按共同日期取交集；
- 年化换算：用假设的年交易日数换算。

### 公式与符号

设某只证券的交易日序列为 `d_1 < d_2 < ... < d_n`，收盘价为 `P_1, ..., P_n`。

相邻交易日简单收益率：

`r_i = P_i / P_{i-1} - 1, i = 2..n`

有效收益观测数为 `n−1`；如果计算这些收益的样本方差，分母是 `(n−1)−1 = n−2`（见 `variance`）。不要把“价格观测数 n”与“收益观测数 n−1”混为一谈。

年化近似：

`R_annual ≈ (P_n/P_1)^(252/(n−1)) − 1`

其中 252 是假设的年交易日数，不是实际日历天数。组合共同日期：

`D_common = D_1 ∩ D_2 ∩ ... ∩ D_k`

交集可能少于任一资产的单独交易日数。

### 可手算的小例子

假设一周五个工作日为周一至周五，某股票只返回四行：

`周一、周二、周四、周五`

- 样本交易日数 = 4，不是 5。
- 缺失的周三是“某个非交易或未返回日期”，可能是节假日、停牌或数据缺失；仅凭这四行不能判断。
- 如果周一收盘 100、周二收盘 102、周四收盘 101、周五收盘 103，则：
  - 周二收益 = `102/100 − 1 = 2%`；
  - 周四收益 = `101/102 − 1 ≈ −0.98%`；
  - 周五收益 = `103/101 − 1 ≈ 1.98%`；
  - 有效收益观测数 = 3，不是 4 个自然日，也不是 5 个工作日。
- 如果把这三个收益当作样本计算方差，分母是 `3−1=2`，不是总体分母 3。
- 若用周五/周一的累计收益 `103/100 − 1 = 3%`，再按 `252/3` 个收益间隔年化，得到的是基于“3 个收益间隔”的换算，不是对未来一年的预测。

另一个例子：A 股票交易日为 `周一、周二、周三、周四`，B 股票为 `周二、周三、周五`，共同交易日是 `周二、周三` 两天；不能把 A 的周四或 B 的周五强行补进组合。

### 前提假设

- 上游返回的日期是实际交易日，且没有漏行。
- 同一市场内日期含义一致；跨市场比较时另行处理日历差异。
- 用户选择的开始/结束日期是自然日边界，过滤后只保留实际交易日。
- 252 只是年化近似；不声称适用于所有市场、年份或个股。

### 边界情况

- 空区间、只有一行、开始日期晚于结束日期。
- 周末或节假日出现在区间内；不应为它们补价格。
- 重复交易日、日期无法解析、时区不一致。
- 停牌、复牌、上市首日、退市日、半日市、临时休市。
- 上游漏行、数据源切换、跨市场组合日期不重叠。
- 用自然日数代替交易日数、用价格观测数代替收益观测数、用 365 代替 252。
