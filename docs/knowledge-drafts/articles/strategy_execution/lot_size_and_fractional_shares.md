# 整手与碎股（Lot Size and Fractional Shares）

## 快速理解

### 一句话解释

本软件买入时只买用户设定交易单位的整数倍，卖出时卖出全部持股；它不支持碎股，也不会根据股票代码自动推断港股每手股数。A 股默认 100 股、港股默认 100 股都只是可修改的研究假设。

### 它解决什么问题

它让回测的成交股数接近真实市场的整数交易单位约束，避免出现“买入 37.4 股”这种无法执行的假设。它也提醒研究者：交易单位因市场、板块和证券而异，不能用一个默认值覆盖所有标的。

### 最常见的误解

- **“软件可以买任意股数”**：买入是交易单位的整数倍；没有碎股。
- **“A 股和港股每手都是 100 股”**：默认值只是研究假设；港股每手数量由用户输入，A 股不同板块和证券也可能不同。
- **“软件会自动读取每手股数”**：不会；港股特别要求用户自行核对并输入。
- **“卖出也必须是整手”**：本软件卖出全部持股，可以一次卖出非整手数量；这不等于支持碎股买入。
- **“整手只影响股数，不影响收益”**：剩余现金、无法买入的资金和交易单位会改变净值路径。

## 软件实践

### 在 Quant Lab 哪里出现

- “成交与费用假设”中的“买入交易单位（股，请核对标的与板块）”。
- 回测买入：按交易单位计算可买手数，资金不足则减少手数，仍不足则订单未成交。
- 回测卖出：卖出当前全部持股，不保留零股。
- 参数敏感性：同一交易单位设置会影响每个参数组合的成交次数和收益。
- 订单表：`shares` 是实际成交股数；未成交时为 0。

### 输入、输出和单位

输入：交易单位 `lot_size`（股）、初始现金、成交价、费用。输出：实际买入股数、卖出股数、剩余现金。

买入时：

`max_lots = floor(cash / (fill_price × lot_size))`

然后从 `max_lots` 开始逐手减少，直到 `股数 × fill_price + 费用 ≤ cash`。

- `lot_size` 必须是大于等于 1 的整数。
- 买入股数是 `lot_size` 的整数倍；卖出股数是当前全部持股。
- 默认 A 股 100 股、港股 100 股，但都可以在界面修改。
- 港股每手数量不由软件验证；用户必须自行核对标的和板块。

### 结果应该怎么读

- 看到买入股数不是交易单位整数倍，说明数据或代码有问题；本软件不会这样成交。
- 看到大量现金剩余，可能是交易单位太大、价格太高或费用使最后一手不可负担。
- 看到卖出股数是奇数或非整手，可能是公司行动、历史持仓或用户输入导致的；当前软件卖出全部持股，不按整手拆分。
- 看到“资金不足以买入一个交易单位”，说明现金不足以覆盖一手价格加费用。
- 不要用默认交易单位推断真实市场规则；以交易所、券商或证券公告为准。

### 当前软件边界

**分层结论**：整数交易单位已实现；碎股未实现；港股每手数量由用户输入，软件不自动验证。

**软件已经计算或显示什么**

- 买入股数按 `lot_size` 的整数倍计算。
- 资金不足时自动减少手数；仍不足则订单未成交。
- 卖出时卖出全部持股。
- 交易单位是回测配置的一部分，保存在实验档案中。
- 订单表记录实际成交股数和未成交原因。

**软件只间接使用什么**

- 交易单位影响可买股数、剩余现金、费用和净值，但不影响信号本身。
- 交易单位不区分板块、上市阶段、证券类型或市场规则。
- 港股默认 100 股来自示例配置，不是从代码或交易所名录推断。

**软件没有提供或没有建模什么**

- 碎股、零股买入或按金额买入。
- 自动读取港股每手股数、A 股板块申报单位或特殊证券规则。
- 零股卖出专用流程、最低交易单位校验或交易所拒单。
- 公司行动产生的零股、配股、合并换股和碎股现金替代。
- 不同市场、板块、证券类型的交易单位数据库。

**核验状态**：

交易单位规则会随市场、板块和证券变化；默认值只是研究假设。S002、S003 官方入口可访问，但具体条款和每手股数仍未逐项核验，NEEDS_REVIEW（核验日期：2026-10-23）。

## 专业原理

### 正式定义

交易单位（lot size / board lot）是买入时允许的最小整数股数单位。若交易单位为 `L` 股，买入股数通常为 `k×L`，其中 `k` 为非负整数。碎股（fractional shares / odd lot）是小于一个交易单位或不是交易单位整数倍的股数。

本软件的买入规则：

`shares_buy = k × L`，`k = max{ k ≥ 0 : k×L×fill_price + fees(k×L) ≤ cash }`

卖出规则：

`shares_sell = shares_held`

### 公式与符号

- `L`：交易单位（股）；
- `k`：买入手数；
- `fill_price`：含滑点的成交价；
- `fees`：该笔成交的费用；
- `cash`：成交前现金；
- `shares_buy`：买入股数；
- `shares_held`：当前持股；
- `floor`：向下取整。

### 可手算的小例子

**例 1：可买 3 手。**

- 初始现金 10,000；
- 成交价 33.00；
- 交易单位 100 股；
- 暂不计费用。
- 一手金额：`33×100=3,300`。
- `floor(10,000/3,300)=3` 手，买入 300 股，花费 9,900，剩余 100。
- 4 手需要 13,200，超过现金。

**例 2：一手也买不起。**

- 初始现金 10,000；
- 成交价 101.00；
- 交易单位 100 股；
- 一手金额：`101×100=10,100`，超过 10,000。
- 可买手数为 0，订单记录为未成交，原因“资金不足以买入一个交易单位”。

**例 3：费用让最后一手不可负担。**

- 初始现金 10,000；
- 成交价 99.00；
- 交易单位 100 股；
- 一手金额 9,900，剩余 100；
- 若佣金最低 5 元、卖出附加费另计，买入总成本 9,905，仍可买 1 手；若一手金额接近 10,000，费用可能让一手也不可负担，程序会减少手数或记录未成交。

**例 4：卖出全部持股。**

- 当前持股 250 股（例如公司行动后形成）；
- 卖出时一次卖出 250 股，而不是只卖 200 股；
- 这不代表软件支持碎股买入，只是卖出全部持仓的规则。

### 前提假设

- 交易单位是正整数，由用户输入；软件不自动推断。
- 买入只能按交易单位整数倍成交；没有部分成交、碎股或按金额买入。
- 卖出全部持股；没有最低卖出单位限制的额外建模。
- 现金、费用和成交价在同一币种、同一市场内计算。
- 公司行动、停牌、涨跌停和 T+1 另由回测规则处理。

### 边界情况

- `lot_size=1`：允许，但仍是整数股；不代表真实市场允许 1 股买入。
- 现金不足一手：订单未成交，不会自动融资或买碎股。
- 价格过高、交易单位过大：可能长期无法建仓。
- 卖出非整手持仓：软件一次卖出全部，不拆成整手和零股。
- 港股每手数量错误：软件不会发现，回测结果可能偏离真实可执行性。
- A 股板块/特殊证券规则：未自动识别，NEEDS_REVIEW。
- 公司行动、配股、合并换股：当前不建模零股和现金替代。
