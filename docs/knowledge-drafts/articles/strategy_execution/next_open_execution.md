# 下一交易日开盘成交（Next-Open Execution）

## 快速理解

### 一句话解释

t 日收盘后形成的信号，只能在 t+1 个交易日开盘时尝试成交；这是本软件回测引擎的固定时序，不是“收盘价下单”或“盘中任意价格成交”。

### 它解决什么问题

它把“知道信号”和“执行信号”分开，避免用产生信号当天的收盘价成交，从而减少同日收盘前视偏差。它也决定了订单、滑点、费用和净值的日期对齐方式。

### 最常见的误解

- **“收盘信号可以按当天收盘价成交”**：不可以；信号在收盘后才完整，最早下一交易日开盘执行。
- **“下一开盘一定成交”**：不一定；零成交量、涨跌停、资金不足或交易单位不足都可能让订单未成交；代码另有 A 股 T+1 防御性检查，但当前日线每天最多一笔订单，正常流程不会同日买卖，因此通常不会观察到该原因。
- **“信号 t 可以用 t+1 开盘价生成”**：t 日信号只能使用 t 日及更早信息；t+1 开盘价是执行价格，不是信号输入。
- **“最后一天会强制平仓”**：本软件不强制末日平仓；最后净值按当日收盘价估值，持股可以保留。
- **“下一开盘成交等于没有偏差”**：它消除了同日收盘成交偏差，但不消除幸存者、数据修订或全样本标准化等偏差。

## 软件实践

### 在 Quant Lab 哪里出现

- 历史回测：注释和页面文案明确“收盘后产生信号，下一交易日开盘尝试成交”。
- `run_backtest`：i 日使用 `close_signals.iloc[i-1]` 作为决策信号，订单在 i 日开盘处理。
- 基准：买入持有信号全为 1，第一个交易日决策为 0，第二个交易日开盘尝试买入。
- 订单表：`decision_date` 是信号日，`date` 是成交尝试日，两者相差一个交易日。
- 净值：成交日用开盘价成交，收盘用当日不复权收盘价估值。

### 输入、输出和单位

- 输入：原始不复权 OHLCV、信号序列（0/1）、回测配置。
- 输出：订单表和每日净值。
- 日期单位是交易日，不是自然日；下一交易日来自输入行情序列的下一行。
- 成交价单位是币种/股；滑点是基点；费用是币种金额。
- 信号序列长度必须与原始行情交易日数量一致；信号只能是 0 或 1。

### 结果应该怎么读

- 看订单表的 `decision_date` 和 `date` 是否相差一个交易日；如果相同，说明时序可疑。
- 看成交价是否来自 `date` 当天的开盘价，并叠加滑点；不是信号日收盘价。
- 看 `status`：`filled` 才是成交；`blocked` 有原因但没有成交。
- 看最后一天：如果没有卖出订单，最后净值仍按收盘价计算持股价值，不会自动清仓。
- 看基准：它也在第二个交易日开盘尝试买入，不是第一天收盘买入。

### 当前软件边界

- 只支持日线；不能用分钟线、盘中 VWAP 或收盘集合竞价价格。
- 订单只在下一交易日开盘尝试一次；没有盘中撤单、改单、排队或部分成交。
- 成交价是开盘价加/减固定基点滑点；不是盘口最优价或成交量加权价。
- 零成交量、A 股简化涨跌停、资金不足和交易单位不足会阻止成交。
- 代码对 A 股卖出保留 `i <= last_buy_index` 的简化 T+1 防御性检查；当前日线引擎每天最多一笔订单，正常流程不会同日买卖，因此 T+1 通常不是当前可观察到的 `blocked` 原因。
- 港股交易单位由用户输入，未模拟 VCM；A 股板块差异未自动识别。
- 费用、滑点和涨跌停都是研究假设，不是完整交易所仿真。

## 专业原理

### 正式定义

设 `S_t` 为 t 日收盘后形成的信号，`open_{t+1}` 为下一交易日开盘价。订单在 t+1 开盘尝试执行：

`decision_{t+1} = S_t`

买入成交价（若成交）：

`fill^buy_{t+1} = open_{t+1} × (1 + slippage_bps/10000)`

卖出成交价（若成交）：

`fill^sell_{t+1} = open_{t+1} × (1 − slippage_bps/10000)`

若没有成交，持仓和现金不变，订单记录为 `blocked`。

### 公式与符号

- `S_t`：t 日收盘信号，0 或 1；
- `open_{t+1}`：t+1 开盘价；
- `slippage_bps`：单边滑点，基点；
- `fill`：成交价；
- `decision_date`：信号日 t；
- `date`：订单尝试日 t+1；
- `status`：`filled` 或 `blocked`。

### 可手算的小例子

假设：

- D1 收盘信号 0；
- D2 收盘信号 1；
- D3 收盘信号 0；
- D3 开盘价 11.00，D4 开盘价 12.00；
- 滑点 2 基点（0.02%）。

则：

- D2：使用 D1 收盘信号 0，不产生订单。
- D3：使用 D2 收盘信号 1，买入；成交价 `11.00×(1+0.0002)=11.002`。
- D4：使用 D3 收盘信号 0，卖出；成交价 `12.00×(1−0.0002)=11.9976`。

如果 D3 开盘成交量是 0，D3 订单会被记录为 `blocked`，原因“零成交量，视为无法成交”；若后续交易日的决策信号仍为 1 且持股仍为 0，该交易日会再次尝试买入。

这个例子只展示价格和日期；实际股数还要受交易单位、现金和费用约束。

### 前提假设

- 行情按交易日升序排列，日期唯一。
- t 日信号只使用 t 日及更早数据。
- t+1 开盘价是当时可观察的执行价格；不使用 t+1 收盘价反推。
- 订单在开盘时一次性尝试；没有盘中价格路径。
- 只做多；卖出全部持股；不加杠杆、不做空。

### 边界情况

- 信号日之后没有下一交易日：不产生订单。
- 下一交易日停牌或成交量为 0：订单未成交；若条件持续，后续交易日重试。
- 代码存在简化的 A 股 T+1 防御性检查（`i <= last_buy_index`）；当前日线、每天最多一笔订单的流程天然不会同日买卖；软件没有完整模拟可用持仓、历史持仓、盘中多订单或交易所级 T+1 制度。
- 涨跌停：开盘价触及假设阈值时，买入或卖出可能被阻止。
- 资金不足一个交易单位：买入未成交。
- 最后一天没有卖出信号：不强制平仓，按收盘价估值。
- 复权价格：信号可使用复权价，成交必须使用不复权开盘价。
