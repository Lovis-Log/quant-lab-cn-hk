# 可复现性与审计（Reproducibility and Audit）

## 快速理解

### 一句话解释

可复现性是别人拿到同一份数据、同一组策略和成本参数、同一训练比例后，能重新算出同一结果；Quant Lab 用实验指纹、原始/信号 CSV 快照和复算来支持这件事，但当前实验没有保存源码提交或输入契约版本。

### 它解决什么问题

它让研究结果不只停留在截图或口头描述。实验档案保存标的、区间、来源、接收时间、复权、策略、成本、训练比例、订单和指标；复算时从存档数据重新运行并核对指纹，能发现输入或配置不一致。

### 最常见的误解

- **“有 audit_id 就等于结果真实”**：指纹只能说明输入和配置相同，不证明策略有效或数据无偏。
- **“复算会重新联网获取最新数据”**：复算使用实验保存的原始/信号快照，不重新请求上游。
- **“audit_id 包含来源、名称和源码提交”**：当前指纹主要覆盖原始 CSV、信号 CSV、策略、成本配置和训练比例；来源、接收时间、市场、代码、名称和复权保存在档案中，但不全部作为独立字段进入指纹。
- **“实验档案保存了源码版本”**：当前没有保存源码提交、依赖版本或输入契约版本。
- **“本地 SQLite 记录不可篡改”**：它是本地研究数据库，不是签名审计系统；有写权限的人可以修改。

## 软件实践

### 在 Quant Lab 哪里出现

- 历史回测“保存实验”：保存标题、假设、笔记、市场、代码、日期、策略、成本、训练比例、指标、订单、来源、复权、接收时间、名称、指纹和两份 CSV 快照。
- 研究笔记：查看实验、导出 Markdown 报告、导出可复现研究包 ZIP、从存档数据重新计算。
- 实验列表：显示 `audit_id`、来源和名称。
- ZIP：`report.md`、`raw_history.csv`、`signal_history.csv`、`assumptions.json`。
- 复算：校验快照 SHA-256，重新运行 `run_experiment`，比较新指纹与保存指纹。

### 输入、输出和单位

实验保存的输入/字段：

- 原始不复权行情快照 `raw_history`；
- 信号价格快照 `signal_history`（可能为前复权/后复权）；
- 策略 `StrategySpec`；
- 成本配置 `BacktestConfig`；
- 训练比例 `train_fraction`；
- 市场、代码、名称、来源、复权口径、接收时间；
- 标题、假设、笔记。

输出：

- `audit_id`：SHA-256 摘要的前 16 个十六进制字符；
- `raw_sha256`、`signal_sha256`：两份 CSV 的 SHA-256；
- 指标 JSON、订单记录；
- Markdown 报告和 ZIP。

### 结果应该怎么读

- 先看 `audit_id`：同一实验复算应得到同一指纹；不同指纹说明输入或配置不一致。
- 看 `raw_sha256`、`signal_sha256`：它们分别校验原始和信号快照；不是实验指纹本身。
- 看来源和接收时间：它们说明数据来自哪里、何时取得，但不进入指纹的每个字段。
- 看复权口径：信号快照可能使用复权价格；原始快照用于成交和估值。
- 看复算结果：复算成功只说明当前代码用存档数据能重算出同一指纹；不证明当时使用的代码版本或未来数据可用性。
- 看 ZIP：包含报告、两份 CSV 和假设 JSON；不包含源码、依赖锁定文件或交易所规则版本。

### 当前软件边界

- 当前实验保存原始/信号 CSV、SHA-256、策略、成本、训练比例、来源、接收时间、市场、代码、名称、复权、指标和订单。
- `audit_id` 覆盖原始 CSV、信号 CSV、策略配置、成本配置和训练比例；不是完整代码/环境指纹。
- `audit_id` 只保留 SHA-256 的前 16 个十六进制字符（64 位），不是完整摘要、数字签名或第三方存证。
- 来源、接收时间、市场、代码、名称和复权保存在实验档案中，但不全部作为独立字段进入 `audit_id`；市场包含在成本配置的 `repr` 中，复权会改变信号 CSV。
- 当前实验未保存源码提交、依赖版本、Python/操作系统版本、输入契约版本、数据库 schema 版本或交易所规则版本。
- 复算使用存档快照，不重新联网获取数据；上游数据修订不会自动进入复算。
- 本地 SQLite 不是不可篡改审计系统；没有数字签名、远程时间戳或第三方存证。
- 旧实验可能没有名称字段；迁移后显示空名称，不能据此断言证券不存在。

## 专业原理

### 正式定义

可复现性（reproducibility）是指使用相同的输入、假设、代码和环境，能够重新得到相同结果。审计（audit）是保存足够证据，使第三方能够检查“用了什么数据、什么配置、什么规则、得到什么结果”。

本软件的实验指纹：

`audit_id = first16hex(SHA256(raw_csv || signal_csv || repr(spec) || repr(config) || str(train_fraction)))`

其中 `||` 表示按顺序更新哈希；`first16hex` 取摘要前 16 个十六进制字符。

### 公式与符号

- `raw_csv`：原始不复权行情 CSV；
- `signal_csv`：信号价格行情 CSV；
- `spec`：策略配置（类型、短窗口、长窗口）；
- `config`：成本配置（市场、初始资金、交易单位、佣金、最低佣金、附加费、滑点、涨跌停）；
- `train_fraction`：训练比例；
- `SHA256`：密码学哈希；
- `audit_id`：16 个十六进制字符的短指纹；
- `raw_sha256`、`signal_sha256`：两份 CSV 的完整 SHA-256。

### 可手算的小例子

假设有两个实验记录，除了训练比例外完全相同：

| 字段 | 实验 A | 实验 B |
| --- | --- | --- |
| 原始 CSV | 相同 | 相同 |
| 信号 CSV | 相同 | 相同 |
| 策略 | `dual_ma, 10, 30` | `dual_ma, 10, 30` |
| 成本配置 | 相同 | 相同 |
| 训练比例 | 0.70 | 0.75 |
| audit_id | 不同 | 不同 |

因为 `train_fraction` 进入哈希，0.70 和 0.75 会得到不同指纹。反过来，如果只改实验标题、笔记、来源显示文字或证券名称，而原始/信号 CSV、策略、成本和训练比例完全不变，`audit_id` 可能不变；这些字段仍保存在实验档案中，但不全部进入指纹。

再假设两个不同股票的历史 OHLCV 恰好完全相同、策略和成本也相同：由于 `audit_id` 的输入不包含代码和名称，指纹可能相同；但实验档案中的市场、代码和名称不同。不要把指纹相同解释为“同一个标的”或“同一个来源”。

SHA-256 本身不适合手算；上面的例子用于核对“哪些输入会改变指纹”，不是让你手算 16 位十六进制。实际复算由程序完成。

### 前提假设

- 原始和信号 CSV 按固定列顺序、固定浮点格式序列化；同一数据应产生同一 CSV。
- 策略和成本配置的 `repr` 稳定；字段顺序或类型变化会改变指纹。
- 训练比例以字符串形式进入哈希；Python float 中 `0.7` 和 `0.70` 是同一个值，`str()` 都得到 `"0.7"`，不会仅因书写尾零产生不同指纹。真正不同的浮点值（例如 `0.7` 与 `0.7000000000000001`）才会改变哈希输入。
- 复算使用同一代码版本；代码变化可能改变信号、成交或指纹。
- 实验档案的 SQLite 数据可读且未被修改；本地数据库没有防篡改保证。

### 边界情况

- 代码版本变化：即使输入相同，信号或成交逻辑变化会改变指纹；当前档案没有保存源码提交，无法自动定位差异。
- 依赖版本变化：pandas/NumPy 行为变化可能影响 CSV 浮点格式或计算。
- 输入契约变化：列名、字段类型或日期格式变化可能使旧快照无法按当前代码复算。
- 上游数据修订：复算使用旧快照，不会自动采用新数据；这保证可复现，但不代表数据最新。
- 旧实验缺少名称：迁移后名称空值可读；不能把空名称当成证券不存在。
- 本地数据库被修改或损坏：SHA-256 校验可能失败；当前没有远程签名。
- CSV 浮点精度：不同平台/版本的序列化可能产生细微差异；当前使用固定 `to_csv` 输出。
- 删除笔记/回收站：实验和附件生命周期不同；删除实验会影响复算证据。
