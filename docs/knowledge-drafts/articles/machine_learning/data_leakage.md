# 数据泄漏（Data Leakage）

## 快速理解

### 一句话解释

数据泄漏是指模型在训练、特征构造、预处理、调参或评估时，使用了决策时点不可能知道的信息，导致样本外结果虚高；Quant Lab 的内置管线对固定流程有防护，但**不是通用泄漏检测器**。

### 它解决什么问题

一个模型在测试集上表现很好，可能不是因为它学到了可用的关系，而是因为它提前看到了答案。数据泄漏把“未来”带进“过去”，让回测和样本外评价失去意义。识别泄漏是金融机器学习中最重要、也最容易被忽略的质量问题之一。

### 最常见的误解

- **“软件会自动检测所有泄漏”**：当前只对固定内置管线做时间切分、间隔和训练集标准化；没有通用检测器。
- **“随机切分没问题”**：时间序列随机切分会把未来样本混入训练。
- **“泄漏只发生在特征里”**：标签构造、缺失值插补、标准化、特征选择、调参和反复评估都可能泄漏。
- **“用了未来数据一定很明显”**：泄漏常常很隐蔽，例如用全样本均值填补缺失、用未来公告修订数据、用当前上市股票回看历史。
- **“标准化不会泄漏”**：如果用完整数据（含测试集）拟合均值和标准差，测试信息就进入了预处理。
- **“留一行间隔就解决了所有泄漏”**：它只防止相邻标签跨入第一个测试日；重叠标签、外部数据和幸存者偏差仍需单独处理。

## 软件实践

### 在 Quant Lab 哪里出现

- `supervised_frame` 要求日期唯一且升序；日期重复或乱序会报错。
- `evaluate_linear_model` 按时间切分训练/测试，训练集为 `samples[:split−1]`，测试集为 `samples[split:]`，索引 `split−1` 作为一行间隔。
- 标准化在 `Pipeline(StandardScaler(), LinearRegression())` 内完成，只在训练数据拟合，再应用于测试数据。
- 训练期交叉验证的每一折都新建 Pipeline，避免先对完整训练集标准化再切折。
- 页面说明强调：特征只使用当日收盘后可知的价格和成交量；标签是下一日收盘收益。
- `lookahead_bias` 与回测引擎也强制收盘信号、下一开盘成交。

### 输入、输出和单位

- 输入：按日期升序、日期唯一的行情表；至少 60 行有效监督样本。
- 特征：当日收盘后可知的五个价格/成交量特征。
- 标签：`next_return_t = close_{t+1}/close_t − 1`。
- 输出：训练/测试预测、MAE、基线 MAE、R²、方向一致率、交叉验证 MAE。
- 单位：收益率误差；泄漏不会改变单位，但会改变指标的可信度。

### 结果应该怎么读

- 如果样本外 R² 异常接近 1、MAE 接近 0，先怀疑泄漏，而不是庆祝模型。
- 检查特征是否使用了 `target_date` 或更晚的数据。
- 检查标准化、缺失值插补、特征选择是否只用了训练数据。
- 检查标签是否与特征同期：特征日 t，标签日 t+1。
- 检查测试集是否在调参、选特征或选区间时被反复使用。
- 检查股票池是否只包含当前仍上市的股票，是否存在幸存者偏差。
- 检查外部数据是否有发布时间、修订时间和可得性限制。

### 当前软件边界

**分层结论：固定内置管线有防护，不代表软件能检测所有泄漏。**

**软件已经实现什么**

- 日期唯一且升序校验；
- 按时间顺序切分，不随机打乱；
- 训练/测试之间留一行间隔；
- 标准化只在训练数据拟合；
- 交叉验证每折单独创建 Pipeline；
- 特征只使用当日及更早的价格和成交量；
- 页面说明标签是下一日收盘收益，不是可执行交易收益。

**软件只间接使用什么**

- 一行间隔防止训练标签直接使用第一个测试日的价格；
- Pipeline 结构防止标准化在折外数据上拟合；
- 时间切分减少未来样本进入训练。

**软件没有提供或没有建模什么**

- 通用数据泄漏检测器；
- 外部数据的发布时间、修订时间、可得性检查；
- 幸存者偏差、退市股票、股票池选择偏差的自动处理；
- 用户自定义特征中的未来信息检测；
- 重叠标签的 purging/embargo 长度选择；
- 特征选择、超参数搜索和模型选择中的泄漏防护；
- 反复查看测试集、可选停止和数据窥探的自动检测；
- 复权口径、除权跳变和停牌导致的信息问题。

**核验状态**：

内置管线的防护已在 `statistics.py` 中核对；通用泄漏检测未实现。该词条保持 `implemented`，但文章明确写出防护范围。

## 专业原理

### 正式定义

设 `I_t` 是在 t 日收盘后可得的信息集。特征 `X_t` 必须只依赖 `I_t`：

`X_t = f(I_t)`

标签可以使用未来信息，因为它是预测对象：

`Y_t = g(I_{t+1})`

若 `X_t` 使用了 `I_{t+1}` 或更晚的信息，就发生前视泄漏。若训练、预处理、特征选择或调参使用了测试集信息，就发生训练—测试污染。

### 公式与符号

- `I_t`：t 日收盘后可得信息集；
- `X_t`：特征；
- `Y_t`：标签；
- `t`：特征日；
- `t+1`：标签日；
- `M`：有效样本数；
- `split = int(M×f)`：切分索引；
- `gap`：间隔行数，当前为 1。

### 可手算的小例子

**例 1：标签泄漏。**

实际下一日收益：

`[2%, −1%, 3%, −2%]`

如果某个“特征”直接等于下一日收益本身，模型预测：

`[2%, −1%, 3%, −2%]`

绝对误差：

`[0, 0, 0, 0]`

MAE：

`(0 + 0 + 0 + 0)/4 = 0`

R²：

`1 − 0/SS_tot = 1`

模型看起来完美，但这个特征在特征日 t 根本不可得；它只是把答案复制了一遍。这是最直接的标签泄漏。

**例 2：标准化泄漏。**

训练特征 `[1, 2, 3]`，测试特征 `[4]`。

只用训练集拟合标准化（总体口径）：

- 训练均值 `2`
- 训练标准差 `√(2/3) ≈ 0.8165`
- 测试值标准化：`(4−2)/0.8165 ≈ 2.4495`

如果用完整数据 `[1,2,3,4]` 拟合：

- 完整均值 `2.5`
- 完整标准差 `√1.25 ≈ 1.1180`
- 测试值标准化：`(4−2.5)/1.1180 ≈ 1.3416`

两个结果不同，因为后一种做法让测试值参与了均值/标准差估计。当前软件在 Pipeline 内只用训练数据拟合，避免这种污染；但用户自定义预处理时仍可能犯这个错误。

**例 3：一行间隔。**

`M=60`、`f=0.70` 时 `split=42`。索引 41 的标签使用索引 42 的收盘价，而索引 42 是第一个测试特征日。把索引 41 排除在训练外，避免训练标签直接使用第一个测试日的价格。

### 前提假设

- 特征在决策时点可得，且数据时间戳可信。
- 标签的定义与交易执行时点一致；当前标签不是可执行收益。
- 训练、验证和测试的划分按时间顺序，且测试集不参与调参。
- 预处理只在训练集拟合，再应用于验证/测试。
- 外部数据的发布时间、修订时间和覆盖范围可核验。
- 股票池和幸存者偏差已被识别；当前软件不自动处理。

### 边界情况

- 随机切分时间序列：未来样本进入训练。
- 用完整数据标准化/插补：测试信息进入预处理。
- 特征选择使用完整数据：选择过程看到测试标签。
- 超参数在测试集上调：测试集不再独立。
- 反复查看测试结果再改模型：信息泄漏。
- 重叠标签：相邻标签共享未来价格；一行间隔可能不足。
- 外部数据修订：使用修订后数据回看历史，可能包含当时不可得的信息。
- 幸存者偏差：只使用当前仍上市的股票，排除退市/失败样本。
- 公告时间戳：财报、政策或新闻的发布时间晚于数据日期。
- 复权价格：复权因子可能使用未来公司行动信息；信号可用复权价，但成交/估值口径要一致。
- 缺失值插补：用未来均值或全样本统计量填补。
- 样本选择：按未来表现筛选股票或区间。
